Help and reference

{{ squiggle() }}

The three questions people ask most: where are my notes? (the folder shown under Folders in Settings), how do I connect Zotero? (export a Better BibTeX file and give Settings its path), and how do I back up? (your notes are plain files; any backup tool works).

Getting started

What a Zettelkasten is

A Zettelkasten (“slip box”) is the note-taking method of the sociologist Niklas Luhmann, who kept around 90,000 paper slips over four decades and credited them with his output. Four principles shape it, and this app:

  1. One idea per note. “Algorithmic governance erodes accountability” is a note; “Notes on chapter 3” is not. Small ideas recombine in ways large ones can’t.
  2. Links are the structure. No folders: notes point to each other, and the web of links grows out of your thinking rather than a scheme decided in advance.
  3. Your own words. Rewriting an idea is where understanding happens. Ahrens (2017) argues that shortcuts around that friction, AI summaries included, defeat the method.
  4. Written for future writing. You write today’s note because some later project will draw on it, so consistency matters more than volume.

Further reading: Sönke Ahrens, How to Take Smart Notes (2nd ed., 2022); Luhmann, “Communicating with Slip Boxes” (1981, trans. Manfred Kuehn); Andy Matuschak’s notes on evergreen notes (notes.andymatuschak.org).

Getting around

Zetteling is one window: the sidebar (your four kinds of note, plus tags, threads, citations, manuscripts, the codebook and stats), the note list, the note, and a side panel with the note’s thread, backlinks, mentions, related notes and the Interrogate tab. The panel button at the top right hides or shows the side panel.

The tour shows each part of the window in turn. It opens by itself the first time you use Zetteling; to see it again, click the compass at the bottom of the sidebar or choose Take the tour in the palette. Arrow keys move through it and esc leaves.

The command palette (⌘K, or Search in the sidebar) finds notes by title and text and runs commands: new note or template, edit, export, lock, go to any page, switch light and dark. Arrows move, ↵ opens, esc closes.

Creating and saving notes

  • Create: New note at the top of the sidebar, or ⌘N. Start blank or from a template.
  • Edit: Edit above the note, or ⌘E. Kind, tags and thread are in the Details panel on the right.
  • Saving happens by itself: a moment after you stop typing, and again when you click Done or leave the note. The label beside Editing shows “Saving…” and “Saved”. A new note is first saved once it has a title and you’ve moved on from the title field, so its filename uses the whole title. Prefer to save only when you press Save? Turn off Save automatically in Settings → Writing.
  • Delete: the bin icon above the note. See Deleting and the trash.

Every note is one Markdown file named with a 14-digit ID (like 20260407164313) and the title. The ID never changes, so titles can change without breaking links.

Where your notes live

In the folder shown under Folders in Settings, labelled In use now. You choose it on first launch; to move it later, see Sync and backup. Settings, the search index and note history live separately, in ~/Library/Application Support/com.shivissar.zetteling/.

Writing notes

Kinds of note

Every note is one of four kinds, each with its own list in the sidebar: research (the default, with the full Zettelkasten machinery), journal (date-stamped entries; ⇧⌘N starts a new one), teaching (syllabi, lecture plans, reflections) and life (everything else). Kinds keep streams apart in lists; links, backlinks, search and related notes all work across them. Change a note’s kind in the editor’s Details panel.

Templates

A new note can start from a template: pick one in the row at the top of a new note, or ⌘K → “New interview memo”. Four come built in:

  • Interview memo: context and consent, a summary in your words, moments that stood out, first codes, follow-ups, a reflexive note.
  • Fieldnote: setting, who was there, what happened, talk, your reactions, analytic asides.
  • Reading note: the source, its argument in one sentence, claims with pages, concepts, method, links to your work, disagreements.
  • Lecture plan: goals, readings, a timed plan, discussion questions, and what to change next time.

Edit them or make your own in Settings → Templates. A template sets the new note’s kind, tags, title and text; {{ "{{date}}" }}, {{ "{{time}}" }} and {{ "{{weekday}}" }} are filled in. Templates are Markdown files in .templates inside your notes folder, so they travel with your notes.

Links and backlinks

While editing, type [[: a picker lists matching notes. ↵ inserts a link; ⇧↵ inserts it with the note’s title as the text. In the file a link looks like [[20260407164313]], or [[20260407164313|your own words]] with custom text. A link to an ID that doesn’t exist yet shows dashed, a reminder of a note to write.

Backlinks appear on every note without any work: the side panel lists each note that links here, with the sentence the link sits in, so you can see why it links without opening it.

Unlinked mentions

Under the backlinks, Unlinked mentions lists notes that use this note’s title, or its main part before a subtitle (“Tethered autonomy” for “Tethered autonomy — working definition”), without linking to it. Link turns the first mention into a link, keeping that note’s wording as the link text; a version of that note is saved first. Locked notes aren’t searched for mentions.

Tags and threads

Tags are comma-separated in the editor’s Details panel; keep them lowercase and hyphenated (sts-theory). Threads are Luhmann’s Folgezettel: named sequences of notes in argumentative order. When you create a note, the Thread section can start a new thread with it, or add it to the end of an existing one. A note can belong to several threads; the side panel shows its neighbours in each. Thread data lives in the note’s frontmatter.

Embedding notes

A line containing only ![[note-id]] shows that note’s whole text in place, in a frame with a link to it (type ![[ to get the picker). Embeds always show the note’s latest text. They nest two levels deep. They’re how manuscripts work, and useful anywhere you want to read several notes as one.

Citations and Zotero

Type @ at the start of a word to search your bibliography and insert a citekey such as @suchman1987. In the note it shows as “Suchman 1987”, with the full reference on hover; the file keeps the citekey, so exports format citations properly.

Setting up:

  1. In Zotero, install the Better BibTeX extension.
  2. File → Export Library, choose the Better BibTeX format (not the built-in BibTeX, which can leave out citekeys), and tick “Keep updated” so the file stays current.
  3. Save it somewhere stable, such as ~/Documents/Zotero/library.bib, and paste its path into Settings → Bibliography.

Zetteling watches the file and picks up new references within seconds. To check auto-export is really on, look under Zotero’s Settings → Better BibTeX → Auto-export.

Note history

Zetteling keeps earlier versions of each note: one at most every 10 minutes while you edit, and always one before a restore, a lock, a link added from Unlinked mentions, a code rename or a manuscript reorder. The clock button above a note opens its history. Pick a version to see its text and what has changed since (− lines are only in that version, + lines only in the note now), then Restore it if you want. Restoring brings back the title, tags, kind and text, and saves the current version first, so you can undo it.

Versions are kept in the app-data folder (up to 200 per note). A locked note’s versions are encrypted, and locking a note encrypts its earlier versions too.

Finding things

Search

The search box above the note list, and ⌘K, search titles, text and tags of every note, with matches highlighted. Search ignores case and word endings, so orient finds orienting and orientation. Plain searches also accept OR (drone OR uav) and a trailing * (drone*).

Search filters

Add filters to any search, in the search box or the palette. They combine: kind:research tag:drones code:trust after:2025.

Research tools

Qualitative coding

Code passages in your interview memos, fieldnotes or any note, then see each code’s passages gathered in the Codebook.

  1. While editing, select a passage (within one paragraph) and press ⇧⌘C, or Code the selected passage in the Details panel.
  2. Type a code, or several separated by commas. Existing codes are suggested as you type; ⇥ completes, ↵ applies. Select an already-coded passage to add another code.

In the file, a coded passage is written [the passage]{.trust .automation}, pandoc’s own notation for a labelled span. It reads clearly in any editor, and exports as ordinary text. In the note, coded passages are highlighted with their codes after them; click a code to open it.

The Codebook (sidebar) lists every code with its definition and how many passages and notes use it, grouped by category. A code’s page shows all its passages by note, codes applied to the same passages, and codes found in the same notes. There you can:

  • write a definition (what counts, what doesn’t) and a category;
  • rename a code, or merge it by giving an existing code’s name: every note is updated, with a version of each saved first;
  • remove a code everywhere, keeping the passages’ text;
  • export its passages, or every code’s, as a CSV for a spreadsheet or analysis software.

Codes can contain letters, numbers and hyphens (spaces become hyphens). Definitions are kept in .zetteling-codebook.json in your notes folder. Locked notes: their coded passages appear in the Codebook only while locked notes are open, read on the spot and never stored in the index; the code: search filter doesn’t see them.

Manuscripts

A manuscript gathers notes into one draft, in the order you choose, under your own headings. Create one from Manuscripts in the sidebar or ⌘K → “New manuscript”. It’s an ordinary note whose lines ![[note-id]] embed other notes, so it always shows their current text.

  • The Manuscript panel beside it lists sections and notes with word counts. Move items up or down, remove a note from the manuscript (the note itself stays), add a note, add a section heading, or add a whole thread in its order.
  • You can also edit it like any note: write introductions and transitions between the embeds, add headings with ##.
  • Export manuscript produces one document with every embedded note’s text in place, links turned into plain text and, if you choose, citations formatted. Tick Start each included note with its title as a heading if the manuscript has no headings of its own.

Exporting

Export a note (the export icon above it), a thread (export this thread on its page) or a tag (export all) to Word, LaTeX, HTML, EPUB, ODT, plain text or Markdown. Pandoc is built in. With Process citations ticked, @citekeys become formatted citations and a reference list from your Zotero file. Links between notes become plain text (their titles, or the link’s own words); embedded notes are included in full.

For PDF, export to Word or HTML and print to PDF; direct PDF needs a separate LaTeX installation. Files go to the export folder set in Settings. Exports of locked notes are not encrypted, and the export page says so.

Writing stats

Totals, words per note, a 30-day sparkline, when in the day you write, your most-linked notes and top tags. Observation only: no streaks or targets.

AI features

Every AI feature is optional and off until you set up a provider; Zetteling works fully without them. The Privacy page lists exactly what each one sends where. Locked notes are never sent to any provider.

Setting up a provider

Settings → AI has two separate slots: chat (Interrogate and tag suggestions) and embeddings (related notes). Chat: Anthropic, any OpenAI-compatible service, Google Gemini, or Ollama on your own Mac. Embeddings: OpenAI-compatible, Gemini, Ollama or Voyage AI. Defaults are filled in (claude-haiku-5-5, gpt-5.4-mini, gemini-flash-latest and gemini-embedding-2, qwen2.5:14b and nomic-embed-text for Ollama, voyage-3.5). Then click Test connection.

Two common mistakes: a chat model in the embeddings slot (or the reverse) fails quietly on every save; and Ollama models must be downloaded first with ollama pull <name>.

Related notes

With an embeddings provider, the side panel lists the notes most similar to the one you’re reading. It is the only AI feature that runs by itself: each note is sent for embedding when you leave the editor or press ⌘S, not while you type. Read the list as prompts for rediscovery, not a measure of closeness: quality depends on the model, the surprising results are usually the useful ones, and cosine similarity over learned embeddings is less principled than it looks (Steck, Ekanadham and Kallus 2024, “Is Cosine-Similarity of Embeddings Really About Similarity?”, Companion Proceedings of the ACM Web Conference 2024, doi:10.1145/3589335.3651526). After switching models, use Reindex all notes in Settings.

Interrogate

The Interrogate tab (⌘I) is a conversation about one note: each message sends the note and the conversation so far. Use it for questions that make you think (“what does this assume?”, “what would refute it?”), and put anything worth keeping into a note in your own words. Conversations are held in memory only and disappear when you quit. For sensitive material, use Ollama, which never leaves your Mac.

Tag suggestions

Suggest tags in the editor sends the title, the first 4,000 characters and your existing tag list, and keeps only suggestions that are already among your tags, so your vocabulary stays consistent. It runs only when you click it.

Choosing providers

For privacy above all, use Ollama for both slots; nothing leaves your Mac, at some cost in speed and quality. For the best chat, a cloud provider such as Anthropic; check its current data policy. For cloud embeddings, OpenAI’s text-embedding-3-small is good value. Read the data-retention policies of aggregators (OpenRouter, Together, Groq, DeepSeek) before sending them anything sensitive.

Privacy and security

Locked notes

A locked note’s text is encrypted on disk: in Finder, other apps, backups or sync services it reads as random characters. Without your password or recovery key, nobody can read it, including you.

  • Set up once in Settings → Locked notes: a password of at least 10 characters (four or five unrelated words work well). You then get a recovery key, shown once. Print it or keep it in a password manager.
  • Lock a note with the padlock above it, or ⌘K → “Lock this note”. Lock a kind (your journal, say) under Always lock these kinds: its notes are locked now, and new ones are created locked.
  • Opening: the first locked note you open asks for the password. They stay open until you quit, or until Zetteling has been idle for the time you choose. If they close while you’re editing, your text is saved first; if it can’t be, the editor asks for the password. ⌘K → “Lock notes now” closes them at once.
  • Remove a lock with the open padlock on a locked note, or Remove all locks in Settings. Change your password in Settings (the recovery key keeps working); forgot it? Use the recovery key.

What stays readable: the title, tags, kind, threads, dates, ID and filename (which includes the title), so lists and threads keep working. The size of the encrypted block hints at the note’s length.

What locked notes don’t do:

  • No AI: never sent to a provider; any related-notes data from before locking is deleted.
  • Search finds their titles and tags, not their text; the text indexed before locking is erased from the index. Links inside them don’t appear as backlinks, and they aren’t searched for unlinked mentions.
  • Exports are not encrypted.
  • Copies made before locking (Time Machine, iCloud or Dropbox version history, Git, earlier exports) stay as they were; the disk may keep old blocks until they’re reused, which FileVault covers.
  • While open, the text is in Zetteling’s memory; quitting is the surest way to close it.

Tampering: GCM detects any change; an altered locked note won’t open, and Zetteling says so. Where the keys are: the wrapped keys and Argon2id settings (never the password or data key) are in .zetteling-vault.json in your notes folder, and a copy travels inside every locked note, so a note still opens with your password if that file goes missing. Back up the whole notes folder, hidden files included (⇧⌘. shows them in Finder). The file: normal frontmatter with locked: true, then a block between -----BEGIN ZETTELING LOCKED NOTE----- and -----END ZETTELING LOCKED NOTE-----.

Limits: standard parts combined in a standard way, but not independently audited. If your work needs certified encryption (some ethics protocols and data-protection rules do), check with your institution, and consider an encrypted disk image or FileVault as well.

Trust model

Zetteling assumes you wrote every note. That holds for a single person on their own Mac, and keeps things simple. It stops holding when notes come from elsewhere: imported Markdown, a folder shared with a collaborator. An untrusted note could contain HTML or script that runs when viewed. If that’s your situation, turn on Sanitise note HTML in Settings → Writing, which strips scripts and other dangerous HTML while keeping Markdown formatting. Other cases (exposing Zetteling on a network, exporting untrusted notes through pandoc, sending them to Interrogate) are covered on the Privacy page.

Your files

Editing in other apps

Nothing locks you in: edit any note in Obsidian, VS Code, vim or TextEdit, and Zetteling picks up the change within a second or two (reload the page to see it). Keep notes at the top level of the notes folder, not in subfolders, and never change the 14-digit ID at the start of a filename: that makes a new note and breaks links to the old one.

Deleting and the trash

Deleting moves the file into .trash inside your notes folder, with a timestamp added (…-mynote.md.20260407164314.deleted). To restore it, move it back and remove the .2026….deleted ending. Zetteling never empties the trash; do that in Finder when you’re sure. A deleted note’s history stays in the app-data folder.

Sync and backup

Your notes are plain files, so any backup works: Time Machine, iCloud Drive, Dropbox, Git, rsync. Back up the whole notes folder, hidden files included (templates, the codebook and the locked-notes key file live there).

Moving the notes folder: Zetteling doesn’t move notes for you.

  1. Quit Zetteling.
  2. Copy (not move) the notes folder to its new place, such as ~/Documents/Zetteling.
  3. Open Zetteling, set the new path under Settings → Folders, save, and relaunch.
  4. Check your note count matches, then delete the old copy a week later.

Version history with Git: in the notes folder, run git init, git add ., git commit -m "start", then commit as often as you like; git log -p <file> shows one note’s history. (Zetteling’s own note history covers recent changes without any setup.)

Several Macs with Syncthing: each Mac runs its own Zetteling on its own copy of the notes folder, and Syncthing keeps the folders in step. Install it (brew install syncthing, then brew services start syncthing), open http://127.0.0.1:8384, pair the devices with Actions → Show ID and Add Remote Device, then share the notes folder (with Staggered File Versioning). Sync only the notes folder, never the app-data folder: its database is per-Mac, and settings.json holds API keys. Simultaneous edits produce .sync-conflict-… files rather than losing anything. Put your .bib file in the same folder to sync it too.

Settings and appearance

Settings (bottom of the sidebar, or ⌘,) holds everything: appearance, folders, writing (autosave, HTML sanitising), templates, locked notes, AI providers and the bibliography. Changes apply at once, except a new notes folder, which needs a relaunch. Settings are stored in settings.json in the app-data folder.

Appearance: a light theme (Meadow, Lagoon, Blossom, Paper) and a dark one (Starlit, Forest, Midnight), whether to follow your Mac, an accent colour, interface and reading fonts, text size, and the background illustrations. The moon or sun button in the sidebar cycles between following your Mac, always light and always dark.

Troubleshooting

Exports fail or produce nothing (perhaps killed: 9)
Run xattr -cr /Applications/Zetteling.app in Terminal once after installing, then try again.
A change made in another app doesn’t show
Reload the page. If it still doesn’t show, check the file is directly in the notes folder, not a subfolder.
The bibliography shows no entries
The file was probably exported with Zotero’s built-in BibTeX format. Export again with Better BibTeX and point Settings at the new file.
A new Zotero reference doesn’t appear
The export isn’t set to keep updated. Check Zotero’s Settings → Better BibTeX → Auto-export; if the file isn’t listed, export again with “Keep updated” ticked.
The @ picker doesn’t appear
No bibliography is set. Add the path in Settings → Bibliography.
Search misses words that are in my notes
The index may be out of step. Quit, delete zettel.db from the app-data folder, and relaunch: it rebuilds from your notes. This is always safe. (Locked notes’ text is never searchable.)
A link shows as broken
Links use the note’s 14-digit ID, not its title. Use the [[ picker to insert it.
⇧⌘C doesn’t code anything
Select some text first, within a single paragraph. If the shortcut is taken on your Mac, use Code the selected passage in the editor’s Details panel.
Locked notes won’t open with my password
Check Caps Lock and your keyboard layout. If you’ve forgotten it, use Use recovery key in Settings → Locked notes. Without the password or recovery key, locked notes can’t be opened.
AI features don’t appear
No provider is set. Choose one in Settings → AI and click Test connection.
Ollama: “connection refused” or “model not found”
Start it with ollama serve (base URL http://127.0.0.1:11434), and check ollama list against the model names in Settings; download missing ones with ollama pull. Remember embeddings need an embedding model such as nomic-embed-text.
Something else
Quit and relaunch first. Logs can be read in Console.app, or with log stream --predicate 'process == "Zetteling"' in Terminal.
