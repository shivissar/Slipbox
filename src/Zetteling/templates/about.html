About Zetteling

Version {{ version }}

A local-first, plain-Markdown Zettelkasten for academic research. Designed around three commitments: your notes are plain text files you own forever, the app respects your privacy completely, and the friction of writing notes by hand is preserved rather than automated away.

What this is for

This is a tool for thinking, not a task manager and not a knowledge base. It is built around the principles of the Zettelkasten method (see help for an introduction). The hope is that by writing atomic notes and linking them, ideas will accumulate, surprise you, and recombine in ways you didn't plan.

Version history

v5.2.0 — current
Tools for research writing. Note history: earlier versions of every note, with what changed and one-click restore. Backlinks with context and unlinked mentions you can turn into links. Templates for interview memos, fieldnotes, reading notes and lecture plans, or your own. Qualitative coding: select a passage, press ⇧⌘C, and see every code’s passages in the Codebook, with definitions, overlaps, rename and merge, and CSV export. Manuscripts that gather notes in order and export as one document. Search filters such as kind:, tag:, code: and after:. A reorganised help page with a contents sidebar, a short welcome tour (the compass in the sidebar brings it back), and an optional daily update check that tells you when a new version is out; you still install it yourself. Exports now turn links into plain text, and two notes made in the same second no longer share an ID.
v5.1.0
Locked notes. Lock any note, or every note of a kind, and its text is encrypted on disk with AES-256-GCM: unreadable in Finder, other apps, backups and sync services without your password or recovery key. Titles, tags and threads stay readable so lists keep working. Locked notes open with your password until you quit or after an idle time you choose, and are never sent to an AI provider. Set up in Settings → Locked notes; the help page lists the exact standards and settings used.
v5.0.1
Autosave. The note you're editing saves itself a moment after you stop typing and again when you leave it; related notes refresh only when you leave or press ⌘S. A new note is created once it has a title. Turn it off in Settings → Writing. The Licence page now lists the third-party software inside the app, and pandoc's licence ships with it. The build pins an older cryptography package so the app still runs on Intel Macs.
v5.0.0
A new look and a single window. The app is now a workspace: sidebar, note list, the note, and a side panel with its thread, backlinks, related notes and Interrogate. Seven themes (Meadow, Lagoon, Blossom and Paper by day; Starlit, Forest and Midnight by night), your own accent colour, five fonts, four text sizes and an illustrations switch, all in Settings → Appearance; by default the app follows your Mac between light and dark. New: a command palette (⌘K) and keyboard shortcuts; typing [[ in the editor opens a note picker, and @ opens the citation picker at the cursor; a list of the notes the current note links to; citations shown as author and year; a first-run welcome screen. Fixes: the export folder chosen in Settings is now actually used (before, the desktop app always overrode it), and the bibliography path follows the same rule; Gemini defaults moved to gemini-flash-latest and gemini-embedding-2 because the old defaults were shut down in 2026, and Settings now warns about retired models; live search works offline because HTMX and the fonts are bundled; search no longer fails on punctuation; a duplicate, unused Markdown renderer was removed. Note interrogation moved from its own page into the side panel.
v4.0.2
Replaced the bibtexparser dependency with an in-house minimal parser in bib.py. Background: v4.0.1 pinned bibtexparser to >=1.4,<2 on the reasoning that 2.x is still in beta, but Briefcase's wheel-only resolver on Python 3.13 couldn't find a 1.x wheel for macOS arm64 and silently dropped the dependency, leaving the bibliography feature permanently inactive. The in-house parser is around 60 lines, handles the Better BibTeX export subset Zetteling actually uses (citekey, title, author/editor, year), verified against a 2,729-entry library. Removes the dependency-resolution problem class entirely.
v4.0.1
Hotfix for the bibliography integration. v4.0.0 shipped with a bibtexparser 2.x beta pulled in during the Briefcase build, whose API differs from the stable 1.x API the Zetteling code is written against. Symptom: configured bibliography paths resulted in zero loaded entries with a silent parse error in the app logs — module 'bibtexparser' has no attribute 'load'. Fix: pinned bibtexparser to >=1.4,<2 in pyproject.toml so the Briefcase resolver stays on stable 1.x until 2.x ships as a stable release (as of this writing, only 2.x betas exist on PyPI). No code changes. If you installed v4.0.0 and wondered why the @citekey autocomplete never worked, this is why.
v4.0.0
Migrated from Flask + pywebview to BeeWare / Toga. Flask still powers all of the application logic; the change is at the packaging and window layer, where a Toga shell now hosts the Flask app in a native macOS window in place of the pywebview wrapper used since v3.3. Your notes, settings, database, and bibliography are untouched — only the window around them is new. A detailed changelog for this release was not reconstructed: the prior project's DEVNOTES.md was not carried over during the port, and a search of the prior conversations returned no retrievable record of the migration discussions. See DEVNOTES.md in the project root and git log for the actual diff.
v3.17.4
The "today's entry" button on the index page is now labeled "new entry" and always creates a fresh journal note titled with the current date and time (e.g. 2026-04-09 14:32) rather than opening any existing entry for today. This supports interstitial-journaling workflows where a scholar logs multiple discrete moments throughout the day rather than appending to a single rolling daily document. The previous v3.14 behavior was a "find or create" shortcut that opened today's existing entry if one existed, which inadvertently made it easy to clobber an earlier entry by clearing the form to write fresh content. The old /journal/today URL still works as a backward-compatibility alias that redirects to the new /journal/new route, so any bookmarks or memorized URLs from before v3.17.4 continue to function. If you ever want to revisit and edit an existing journal entry, find it through the journal kind filter, search, or any tag view, and click into it normally — nothing about editing existing entries has changed. No code or schema migration is needed for this upgrade.
v3.17.3
Corrected the LICENSE file to byte-perfectly match the canonical PolyForm Noncommercial 1.0.0 text published at polyformproject.org. The v3.17.1 and v3.17.2 releases shipped a LICENSE file reproduced from memory that contained three small deviations from the canonical version: the "Required Notice" example in the body of the Notices section had been substituted with the author's name instead of preserving the canonical "Yoyodyne, Inc." placeholder (the real Required Notice for this project is in the copyright header at the top of the LICENSE file, which is the correct placement); the Fair Use section had a double space where canonical has a single space after "law."; and the Patent Defense section had a line break in a different position than canonical (same words, different whitespace). None of the deviations altered the legal meaning of the license, but for a document whose text is legally operative, byte-identity with the canonical source matters. The corrected file is now verified against the canonical text via sha256 hash comparison. If you installed v3.17.1 or v3.17.2, upgrading to v3.17.3 is recommended so your copy of Zetteling matches the authoritative PolyForm text. No code changed.
v3.17.2
Added a License page accessible from the footer, next to Privacy. The page shows a plain-English summary of what PolyForm Noncommercial 1.0.0 allows and prohibits, notes the distinction between "source-available" and OSI-approved "open source" for readers who care about licensing terminology, and reproduces the full canonical license text below the summary so users can read the exact operative language without leaving the app. No other changes from v3.17.1.
v3.17.1
License and metadata release. Zetteling is now published under the PolyForm Noncommercial License 1.0.0, a source-available license drafted in 2020 by the PolyForm Project to fill a longstanding gap in the software licensing ecosystem: it permits free use, modification, and redistribution for noncommercial purposes (including personal use, academic research, teaching, and use by nonprofits, educational institutions, and government bodies) while explicitly prohibiting commercial use. This is a "source-available" license, not an OSI-approved "open source" license in the strict sense, because the OSI definition prohibits licenses that restrict commercial use. The choice reflects the project's intent: Zetteling is free for other scholars, students, and research institutions to adopt and extend, but not for anyone to turn into a paid hosted service or commercial product. See the LICENSE file in the project root for the full text, and the License section of the README for a brief summary. No code changes in this release — this is a metadata-only bump that adds the LICENSE file, an SPDX identifier header to every Python source file, and a License section in the README.
v3.17
Security and robustness hardening pass driven by three external audits. Shipped: SQLite connection timeout + WAL mode + explicit rollback, defensive JSON parsing in tag queries, index on modified column, startup probe for sqlite_vec extension loading, MAX_CONTENT_LENGTH cap, SECRET_KEY startup warning, optional HTML sanitization via a new sanitize_note_html setting (defaults off, requires bleach when enabled), embedding content-hash caching to skip redundant API calls on unchanged notes, automatic invalidation when the embedding provider/model changes, and retry with exponential backoff on transient embedding failures. New trust model section on the privacy page documenting the six workflow changes (imports, Syncthing, remote deployment, public publishing, LLM pipelines, Pandoc export) that break Zetteling's default "all notes are self-authored" assumption, with concrete mitigations for each. Not shipped: several misdiagnosed concerns from the audits (path traversal, SQL injection, CSRF for local use, etc.) — see DEVNOTES.md for the full list of considered-but-rejected items and why.
v3.16
Streaming chat responses. The Interrogate feature now uses Server-Sent Events to stream tokens from the provider as they are generated, rather than waiting for the complete response. For Ollama on a Mac Mini this drops perceived latency from "10-second blank page then everything appears" to "text starts appearing within half a second and scrolls in as it generates". Total generation time is unchanged — the change is that you are reading for most of it instead of staring at nothing. The Ollama request body also now includes a keep_alive: 10m flag so the model stays loaded in RAM between turns instead of cold-starting each request. Streaming is opt-in per provider via a duck-typed chat_stream method; Ollama is the first one, Anthropic / OpenAI / Gemini / Voyage keep working via a fallback path that returns the whole response as one chunk (same client code path, no visible difference except the obvious lack of token-by-token streaming). Based on a user report from daily use of v3.15.
v3.15.2
Documentation-only patch. macOS Gatekeeper blocks double-clicking an unsigned shell script the first time it's downloaded, which meant new users hit a warning on Install.command before the installer had a chance to run its internal quarantine-stripping command (chicken-and-egg). The workaround has always been to run the installer from Terminal via bash Install.command, which bypasses Gatekeeper entirely. This release documents that workaround prominently: new QUICKSTART.md + quickstart.txt files in the zip root, an updated UPGRADING.md with a Gatekeeper section above the fold, and a rewritten Option 1 in README.md that walks through the bash + Install.command flow and the fallback behavior when pywebview doesn't install cleanly. No code changes; if you're already on v3.15.1 and double-click is already working for you, this upgrade is optional.
v3.15.1
Hotfix for v3.15. The Install.command installer only set up the headless dependencies in the venv, leaving pywebview uninstalled. Double-clicking Zetteling.command then failed at the "import webview" step and produced a confusing error telling the user to run plain pip, which didn't help because plain pip installs into whichever Python is on PATH (often anaconda's base environment), not into the venv. Three fixes: Install.command now installs requirements-desktop.txt into the venv as a second step after requirements.lock; Zetteling.command probes whether webview is importable in the chosen Python and falls back to browser mode (auto-opening http://127.0.0.1:5005) if not; desktop.py's error message now mentions the venv pip path explicitly so anyone who runs it manually sees the correct invocation. pywebview itself is pinned to 6.1 in requirements-desktop.txt for reproducibility.
v3.15
Three fixes in one patch release. First: a double-clickable Install.command for people who don't want to touch a terminal — creates a project-local virtual environment, installs all dependencies with visible progress, clears macOS Gatekeeper quarantine attributes, and reports success with the next step. Safe to re-run on upgrades. Second: the troubleshooting FAQ at the bottom of the help page is now styled with a subtle background and left border on each answer, so the entries are visually separated and readable in both light and dark mode (previously the definition list was unstyled and the dd blocks blended into the body background). Third: a full rewrite of the privacy page to reflect the current state of the AI integrations — it now covers Google Gemini (added in v3.11 but missing from the page until now), gives an explicit per-feature breakdown of which AI features transmit data and when, and flags the one case where data can leave the machine without a button click (semantic search embedding on every note save, if an embed provider is configured). The opening and closing paragraphs have been rewritten to remove the earlier claim that "nothing is transmitted, ever" — that was accurate when written but became misleading after M4 shipped.
v3.14
The kind axis: notes are categorized by purpose into research, journal, teaching, or life. Research keeps the full Zettelkasten machinery (tags, threads, refs, wikilinks, semantic related-notes); the other three streams are kept distinct so journal entries and teaching plans don't mix with research indexes. The index page has kind tabs; the nav has kind links; the new-note form has a kind selector; the journal kind has a "today's entry" shortcut that creates or resumes a day-stamped entry. Cross-kind links, backlinks, and semantic search still work across the whole corpus — kinds segregate indexes, not the corpus itself. Legacy notes are treated as research automatically.

Bare anchor tags throughout the app were rendering as default-browser-blue (also unreadable and inconsistent with the accent color used by the styled link classes). v3.12 (M4.3 + M4.4)
Note interrogation and tag suggestions, the final two M4 milestones. Click "interrogate" on any note view to open a chat sidebar where the note is in context — pick from suggested Socratic prompts ("what does this assume?", "where is the argument weakest?") or write your own. The conversation is ephemeral by design; if something useful comes up, write it as a note in your own words. The "Suggest tags" button in the editor calls the AI for 3-5 tag suggestions drawn strictly from your existing tag vocabulary — the parser refuses any invented tags. Both features work with all four chat providers (Anthropic, OpenAI-compatible, Gemini, Ollama).

v3.10 (M4.2)
